Le harnais est-il mort ?
Je l'ai démonté pièce par pièce.

Un plugin d'équipe Claude Code (skills, hooks, sous-agent, micro-outil, évals) est démonté une pièce à la fois, sur trois tailles de modèle, avec des tâches dont la réponse se vérifie automatiquement. Avant les mesures, à vous de jouer : chaque pièce compense-t-elle le modèle, ou gouverne-t-elle ?

Le débat

Position A

« Le modèle absorbe le harnais »

  • Jediah Katz, « Is the Agent Harness Dead? » (vidéo, 2026).
  • Phil Schmid ne garde que bash et un visualiseur de médias : « Task completion stayed in the same range » (01/09/2026).
  • Railway fusionne 12 skills en un seul skill routeur (« Skill Issue », 24/06/2026).
Position B

« Il compte plus que jamais »

  • Anthropic : l'espace des harnais intéressants ne rétrécit pas quand les modèles progressent, il se déplace (24/03/2026).
  • Birgitta Böckeler : des guides avant l'action, des sensors après (martinfowler.com, 02/04/2026).
  • Katz, seconde partie (d'après les chapitres de la vidéo) : l'infrastructure, la confiance et la sécurité, l'efficacité restent hors du modèle.

Personne ne publie de mesure pièce par pièce, sur plusieurs tailles de modèle. C'est l'objet de ce banc.

La grille

« every component in a harness encodes an assumption about what the model can't do on its own »
Anthropic, Harness design for long-running application development
compense

La pièce compense le modèle

Prompt détaillé, planification imposée, micro-outil, sous-agent, contexte injecté. Elle encode « le modèle ne sait pas… ». Si le modèle progresse, elle peut devenir inutile.

gouverne

La pièce gouverne

Règle, sécurité, vérification, coût : un hook qui bloque une commande, un hook qui lance les tests, une éval. Elle vaut quel que soit le modèle.

Refaire l'expérience

git clone https://github.com/mekkiamiri/harness-teardown
cd harness-teardown
python3 -m unittest discover -s tests       # le banc, sans appel de modèle
python3 teardown/variants.py                # 12 variantes du plugin, validées
python3 teardown/run.py                     # le plan des exécutions (rien n'est lancé)
